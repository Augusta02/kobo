# Kobo

Kobo is a household finance app for sharing bills, expenses, savings goals, and recurring payment rotations. The repository contains a FastAPI backend and an Expo/React Native mobile client.

## Project structure

```text
.
├── app/                 # FastAPI backend
│   ├── core/            # Settings, Firebase, and security
│   ├── db/              # asyncpg pool and SQL migrations
│   ├── jobs/            # Scheduled reminders
│   ├── routers/         # API routes
│   ├── schemas/         # Pydantic models
│   └── services/        # Splitting, receipts, rotations, and push notifications
├── scripts/             # Maintenance scripts, including migrations
├── HearthApp/           # Expo/React Native mobile client
├── .env.example         # Backend environment template
├── requirements.txt     # Backend dependencies
└── progress.md          # Development progress log
```

## Features

- Firebase Authentication with server-side token verification
- Household creation, invitations, membership, and admin transfer
- Shared bills with contributions, equal splits, and settlement tracking
- Shared expenses with receipt uploads and AWS Textract total extraction
- Recurring payment rotations with due-date reminders
- Savings goals with participant shares and ongoing contributions
- Firebase Cloud Messaging device registration and scheduled reminders
- SQL migrations managed without an ORM
- Swagger/OpenAPI documentation from FastAPI

## Requirements

- Python 3.12+
- PostgreSQL
- Node.js and npm
- Expo-compatible development environment
- Firebase project with Authentication enabled
- AWS account with an S3 bucket and Textract access if receipt scanning is used

## Backend setup

From the repository root:

```bash
python -m venv .venv
```

Activate the virtual environment, then install dependencies:

```bash
# macOS/Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

Create a `.env` file from the template:

```bash
cp .env.example .env
```

Set the values for your local PostgreSQL database, Firebase service-account JSON file, and AWS S3 bucket. Keep `.env`, Firebase credentials, and AWS credentials out of version control.

Run the database migrations:

```bash
python -m scripts.migrate
```

Start the API:

```bash
uvicorn app.main:app --reload
```

The API is then available at:

- Health check: <http://localhost:8000/health>
- Swagger UI: <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>

## Mobile app setup

Install the client dependencies:

```bash
cd HearthApp
npm install
```

Start Expo:

```bash
npm start
```

Useful platform commands:

```bash
npm run android
npm run ios
npm run web
```

The mobile app currently uses the API client in `HearthApp/src/lib/apiClient.ts`. Update its API configuration for the backend address reachable from the selected simulator, emulator, or physical device.

## Environment variables

The backend reads configuration from `.env`:

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection string |
| `ENVIRONMENT` | Runtime environment name |
| `FIREBASE_WEB_API_KEY` | Firebase web API key |
| `FIREBASE_CREDENTIALS_PATH` | Path to the Firebase Admin SDK credentials JSON |
| `AWS_ACCESS_KEY_ID` | AWS access key |
| `AWS_SECRET_ACCESS_KEY` | AWS secret key |
| `AWS_REGION` | AWS region |
| `S3_BUCKET_NAME` | S3 bucket used for receipt images |

## API areas

The backend exposes routes for:

- `/households` and `/invites`
- `/bills`
- `/expenses`
- `/rotations`
- `/goals`
- `/devices`
- `/jobs`
- `/health`

Authentication-protected routes expect a Firebase ID token. The complete request and response schemas are available in the generated Swagger UI.

## Database migrations

Migrations live in `app/db/migrations/` and are applied in the order listed in `scripts/migrate.py`. Applied migrations are recorded in the `schema_migrations` table.

When adding a migration:

1. Add the SQL file under `app/db/migrations/`.
2. Append its filename to `MIGRATION_ORDER` in `scripts/migrate.py`.
3. Run `python -m scripts.migrate`.

## Development status
